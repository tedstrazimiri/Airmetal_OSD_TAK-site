Nordic DFU metadata and controller identity

This offline inspection reads the nested nordic/TacCtrl_1_3_6.zip from the decoded Tac.Ctrl update. It does not execute firmware or access hardware. Machine-readable findings and all field offsets are in nordic-metadata-analysis.json; reproduce with scripts/analyze_nordic_metadata.py using /usr/bin/python3.12.

The manifest declares an application update. The init packet also declares application type, zero SoftDevice bytes, and zero bootloader bytes. This is controller application firmware; it is not an image recovered from the external IRONghost QS transmitter or RF video receiver.

The declared size equals the extracted BIN size. Reversing the stored hash bytes gives the computed BIN SHA-256 exactly, following Nordic’s hash serialization. The DFU integer 1 is distinct from the application’s 1.3.6 string. Hardware integer 52 is not an exact chip identity. The official Nordic CLI maps SoftDevice ID 0x100 to S140 7.2.0.

The signature has the expected length and both scalar values lie within the P-256 group order. Signer authentication remains unverified: this application-only ZIP supplies no trusted Orqa public key. A hash match proves internal consistency, not origin. According to Nordic’s init-packet implementation, the signed message is the serialized InitCommand at DAT bytes [9,73), whose SHA-256 is f54a9dc30bfc9c0452fd09ccac0b3a6683533cab0386eebc7d1b2ee3183ca56e. Signature encoding follows Nordic signing.py.

Architecture and load base

At BIN offset 0x00, the initial stack word is 0x20040000. At 0x04, the reset vector is 0x00027375, indicating Thumb entry at 0x27374. Loading at 0x27000 maps this to file offset 0x374. Many literal pointers then resolve exactly to the embedded source-path strings listed below. These mutually consistent observations strongly support a Nordic Cortex-M/Thumb application loaded at 0x27000, ending at 0x6e3ac exclusive.

No exact nRF model is claimed from stack layout or DFU hardware integer alone.

The HID descriptor retains 16 one-bit buttons plus eight 16-bit axes, including the duplicate Slider usage, and hash 1e12645e986407d42f6938acf1316cab3bea3c59ea4e368793e60419043c62ca. This ties the recovered firmware implementation to the observed controller USB interface. It does not establish that the physical controller currently runs version 1.3.6.

Whole contiguous configuration/interface/endpoint records from the capture were not found in the BIN. Their construction remains a code-tracing question. Source comparison: evidence/usb/rea-usb-snapshot.json.

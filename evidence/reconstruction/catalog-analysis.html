Parameters and USB identity

All 97 retained PARAM_VALUE frames match raw table names, four value bytes and type bytes by index. The compiled table starts at 0x6b254 with 97 records of 24 bytes. Wire responses declare 96 while returning indices 0–96. Duplicate names remain separate indexed entries.

The four value bytes are preserved exactly. The firmware uses IEEE754 float32 values even for entries whose MAVLink type code denotes an integer; callers must not silently reinterpret those bytes as an integer union. The exact 16-byte name is retained, including names occupying all 16 bytes.

The 18-byte USB device descriptor at file 0x40488 and 56-byte HID report descriptor at 0x46654 exactly match the retained laptop capture. The HID producer is 0x56038; submit routine 0x63434 sends 18 bytes from RAM 0x200050ac, with class init 0x634cc and callback 0x6346c. These roles are analyst labels supported by saved code, not recovered vendor symbols.

Searchable code and resources

The compact runtime asset JSON supplies parameters, descriptors, strings, source-path xrefs, function addresses/calls, analyst roles and WAV metadata. The evidence catalog adds source hashes, call-edge line anchors, and raw literal-pool words. Source-module associations use explicit assertion/source-string xrefs only; no membership is inferred from neighboring addresses.

Call edges come from direct named calls in the preferred decompiler export. Indirect-call expressions are counted but their targets are not guessed. Raw literal words retain their addresses and referencing functions; candidate SRAM/peripheral/image classifications describe ranges, not proven access semantics.

The package manifest and 103 WAV headers provide the audio resource map. WAV bytes remain in the original extracted tree. Resource token matches are textual anchors rather than proof that every prompt is reachable.

Repeatability and limitations

Run python3 scripts/reconstruct_tac_assets.py from the project root. Use --check to compare deterministic regenerated output with saved files. The exact firmware hash is mandatory; unknown images fail before fixed offsets are interpreted.

Outputs: tac_reconstruction/data/firmware_assets.json, evidence/reconstruction/firmware-catalog.json, and this report. Tests in tests/test_tac_assets.py compare retained wire bytes, raw firmware records, descriptors, graph consistency and repeatability.

  • Original vendor symbols, build system and complete source are not recovered.
  • Function calls are parsed from preferred saved decompiler text, not a complete machine-code call graph.
  • Indirect callback targets and SDK SoftDevice implementation are not exhaustively resolved.
  • Printable runs can be coincidental instruction/data bytes; only referenced/path entries have additional evidence.
  • Source associations require explicit saved xrefs; no function is assigned a source module from address proximity.
  • Physical GPIO routing, electrical timing and external radio firmware are outside this catalog.
  • The STM-associated image is opaque and no STM executable behavior is recovered here.
  • Saved hardware captures establish interface behavior at capture time, not exact installed firmware identity.

This catalog supports a runnable reconstruction; it is not the original vendor source, a flashable replacement, or a claim that every catalogued function has been reproduced.

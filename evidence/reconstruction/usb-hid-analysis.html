USB and HID behavioral reconstruction

Input: Nordic Tac_Ctrl.bin, SHA-256 4c79b25623f07bfc62e8f223e8fbda30b0aba643277d9e13f1fadb6bd15931dd, loaded at 0x27000. Implementation: tac_reconstruction/usb.py, hid.py. Focused assembly is retained in usb-hid-assembly/; the independent review is usb-hid-review.md.

Surface Source Implemented behavior
USB service scheduler 0x5a550 Request queue, then parameter queue, then five periodic slots; heartbeat at0 and position at2. Steps are invocations, not milliseconds.
Local heartbeat 0x5aaa8 and retained captures Exact nine-byte payload 050000000203190303; fixed-length MAVLink2 serialization.
Parameters 0x5a9dc, table 0x6b254 97 entries allocated immediately, including sequence numbers; transmitted count96; raw float bytes/types/names preserved.
Capability 0x5a6d0 Declared60-byte payload, transmitted44-byte packet prefix. Missing bytes and CRC are not fabricated.
Input dispatch 0x5a768, 0x5ab18 Heartbeat, list request, COMMAND_LONG512/param1=148, COMMAND_LONG179. Unsupported commands are recorded and ignored.
Parser completion 0x59a4c, 0x59fcc, 0x5a768 CRC-failed unsigned known messages can dispatch because parser status2 is nonzero. Strict CRC rejection is an explicit analyst option.
Home staging 0x5ab18, 0x5a550, 0x4d888 Binary32 coordinate multiplication by1e7, signed conversion; latitude then longitude in Ghost payload; command179 success ACK.
Position 0x5a8b0 uint8 counter increments even when zero coordinates suppress output. Source byte swapping, overlapping field reads and heading arithmetic preserved.
HID producer 0x56038, helpers 0x55fd8, 0x56006 18-byte report from processed stick arrays, switch bits and wheels; stale first-switch bytes on values0/2 and 2048 endpoints preserved.

All 31 retained heartbeats,241 parameter packets and both44-byte capability prefixes match modeled bytes:274 comparisons. Verification hashes each original capture, confirms every decoded frame occurs at its retained stream offset, then compares output. Sequence/system IDs are seeded from the individual packet for these comparisons. The separate97-response queue test checks sequential generation and source-order behavior. These checks do not establish scheduler timing or installed firmware identity.

The USB position implementation intentionally retains suspicious source behavior. Coordinates are byte-swapped from telemetry RAM; altitude receives no meter-to-millimeter conversion; vy reads part of longitude; vz reads altitude storage; heading uses the source's multiply-by10000 and uint16 truncation. No live position output was observed, so this path is validated by code/assembly and fixed synthetic state only.

HID accepts already-processed values at the input-array boundary, not physical ADC readings. The descriptor has eight wire axes, while Linux exposed seven due to duplicated Slider usage. The producer's stick map reaches2048 although the descriptor declares2047. Hardware control names are not assigned by this model. The report producer itself has no saved raw HID packet oracle, so its tests are static arithmetic vectors rather than a claim of live equivalence.

Queue limits and overflow

Raw descriptors at 0x662ec (requests) and 0x66300 (parameter replies) contain capacity10 and100 respectively, element size296, mode1. Queue helpers 0x31990, 0x31a04, 0x31a4c and 0x31bbc establish that mode1 rejects newest when full; wrappers 0x5a698/0x5a6b4 ignore error4. The backing buffers contain capacity+1 physical slots for the ring implementation.

Parameter packing allocates its sequence before each enqueue. With97 responses already queued, a second list request retains only its indices0–2 and drops3–96, but advances the sequence97 times. Request-queue drops allocate no output sequence because reply construction occurs when servicing the request. Tests compare descriptor words to the original image and exercise both overflow paths. Dropped counts are model diagnostics, not new firmware messages.

Explicit boundaries

  • This is an offline Python model, not ARM instruction emulation or vendor C source.
  • USB buffer resynchronization and input size are bounded analyst policies. Unknown message CRC extras are not invented.
  • The generated firmware parser's zero-payload state-machine edge case is not reconstructed; the model raises a boundary error for such input.
  • Signature bytes are retained as an input flag but cryptographic validation and full signing policy are not reconstructed.
  • Bad-CRC dispatch is a saved-code finding, not a malformed-message hardware experiment. strict_crc=True deliberately diverges from that firmware behavior.
  • Float-to-int behavior outside finite signed32-bit range raises a boundary error rather than guessing processor behavior.
  • Whole-boot state, interrupts, USB driver completion, concurrency and elapsed timing are not reproduced.
  • ACKs and staged packets in tests are inert byte arrays. No commands were sent to connected hardware during reconstruction.

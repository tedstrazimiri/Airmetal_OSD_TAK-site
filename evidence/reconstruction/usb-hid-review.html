Independent USB/HID reconstruction review

Read-only review of tac_reconstruction/usb.py and hid.py against retained decompilation, focused instruction listings, raw firmware literals and saved captures. This review executed no firmware and accessed no hardware. Findings apply to the recovered v1.3.6 Nordic application, SHA-256 4c79b25623f07bfc62e8f223e8fbda30b0aba643277d9e13f1fadb6bd15931dd.

Concrete parser findings

The initial reconstruction rejected CRC-bad input frames. That differed from the saved firmware: evidence/firmware/ghidra-export/00059a4c.c, cases 0x0d/0x0e, sets the return status to 2 on CRC failure and copies the completed message. Wrapper 00059fcc.c returns that status unchanged. In evidence/firmware/ghidra-focused/0005a768.asm, instructions 0x5a78e–0x5a790 compare the parser result with zero and skip dispatch only for zero. Consequently, a complete unsigned packet with a recognized message ID can reach the adapter dispatcher despite a CRC error. This is static evidence, not a live malformed-packet experiment. The final implementation preserves this behavior while offering an explicit strict policy.

Zero-length incoming payloads are another fidelity boundary. 00059a4c.c enters payload state 0x0b after the final message-ID byte without a zero-length special case. The next byte is stored as payload, the 8-bit index increments, and only then is it compared with the declared length. An ordinary framed parser that treats the next two bytes as CRC does not reproduce that state machine. The reconstruction should reject this as an explicit boundary until the full state behavior is modeled.

The signing path is also distinct from cryptographic authentication. 00059278.c returns success immediately when the signing-context pointer is null. A model accepting a signature-bearing frame without validation must record that fact; it must not claim to have authenticated the signer. This review did not establish every runtime signing-context transition.

Static limits

  • Parser recovery remains a modeling boundary. A subsequent raw-descriptor review recovered USB queue capacities10/100 and reject-newest overflow; these are now implemented and tested, as described in usb-hid-analysis.md.
  • Successful saved-capture comparisons cover the observed byte sequences, not all scheduling, fragmentation, malformed input, or concurrent input behavior.
  • The HID model begins with processed control values; ADC acquisition, filtering/calibration, transport callback timing and physical control labels are outside this reviewed producer.
  • Out-of-range and nonfinite float-to-int behavior remains an explicit boundary rather than an invented conversion result.
  • Exact descriptor matches associate the recovered application with the observed controller interface; they do not establish the currently installed firmware release.

The review also corrected the catalog label for 0x632c2 to byte_swap_u16, and added the new focused USB/HID export directory to the catalog input inventory.

Integration review closure

A later read-only review found snapshot effects shared by reference and scenario input opened before file-type checking. The final harness deep-copies snapshot effects; the Linux CLI uses O_PATH metadata inspection and reopens only a verified regular inode through procfs. Regression tests cover snapshot isolation and non-regular input rejection. No physical device was used to test the guard.

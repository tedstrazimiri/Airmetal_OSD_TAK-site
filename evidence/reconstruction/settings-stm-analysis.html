TAC 1.3.6 offline reconstruction: settings, calibration, input filtering, and STM link

Date: 2026-10-11. Implementations: tac_reconstruction/settings.py, tac_reconstruction/stm.py, tac_reconstruction/input_filter.py. Validation: tests/test_tac_settings_stm.py (35 tests) and tests/test_tac_input_filter.py (11 tests), all 46 passing. This is an offline behavioral model; no firmware execution, hardware/device/network I/O, flashing, or changes to the Ghidra database occurred.

Input: evidence/firmware/nordic/Tac_Ctrl.bin, base 0x27000, 291756 bytes, SHA-256 4c79b25623f07bfc62e8f223e8fbda30b0aba643277d9e13f1fadb6bd15931dd. Code references refer to existing evidence/firmware/ghidra-export/<address>.c. Critical record field widths and startup counter increments were also checked using GNU ARM objdump in Thumb mode. Binary constants were independently compared against implemented menu labels, profile bytes, and calibration words.

Implemented surface

  • Nine-row settings menu, exact order/IDs/labels, bounded previous/next movement, six visible rows, confirmation counters, voice-pack transfer-mode entry/cancel, volume/language/display/radio/cable mutations, and persistence effects.
  • Logical settings records, version-4 migration, zero cable setting repair, boot counter, six opaque channel-profile records, and the traced factory-reset subset.
  • Full and center-only calibration sample capture, default fallback bounds, timer-step sequencing, display target coordinates, downstream center order, and two 56-byte persisted calibration records.
  • Four quadratic boundary coefficient triples per gimbal, quadrant-dependent nonlinear sample correction, output scaling/clamps, and explicit finite arithmetic domain.
  • Four 100-sample moving averages, conditional replacement when the average is within 7 counts of the new output, accepted-call counters, and bounded center drift.
  • Stateful STM command and audio framing, CRC, shared-buffer retention, complete-frame RX status handling, signature handshake, first-boot request, queue order/capacities/overflow modes, muted-audio consumption, and mapped voice token names.

Unimplemented algorithms are explicit boundaries below. Methods return inert Python data/bytes; names such as persist, stm_command, and audio token strings do not perform corresponding real-world actions.

Settings menu and record evidence

Reset entry 0x27378 copies flash 0x6daa8 to RAM 0x20003074..0x20003978. Flash 0x6e01c therefore initializes the menu at RAM 0x200035e8. Nine 33-byte records each contain 30 bytes of label, item ID, current value byte, and UI confirmation byte. Labels and IDs were read directly from the binary.

Index Item ID Label Recovered transition at 0x5ee1c
0 0 Gimbal recalibration Second press starts 0x516d8(0) and clears confirmation
1 1 Gimbal center recalibration Second press starts 0x516d8(1) and clears confirmation
2 2 Change voice pack Second press queues STM command 3, value 1; navigation queues value 0
3 8 Cable length Raw value below 160 increments by 10; otherwise becomes 10; displayed as raw times 10 metres
4 3 Audio volume Values below 5 increment; otherwise zero
5 4 Audio Language Zero becomes 1; any nonzero becomes zero; labels ENG/UKR
6 5 Display Zero becomes 1; any nonzero becomes zero; changes display timer and persists
7 6 Radio Zero becomes 1; any nonzero becomes zero; persists
8 7 Factory reset Second press calls the traced reset helpers, then clears confirmation

Events 3/4 move one row up/down with bounds 0..8. Six-row scroll origin is adjusted only at the visible boundary. Navigation resets the global press counter and the destination row's confirmation byte. Event 5 increments that global counter and writes its low byte to the selected row. Other events only render. A model press(item_id) convenience method selects through these navigation events, then sends event 5; it is not a recovered hardware API.

0x5edb8 initializes current menu values from the runtime records. 0x5d068 performs this during UI setup. Display and Radio labels are kept as firmware UI labels; the model does not equate these bytes with directly toggling a power rail or an RF transmitter.

0x51e8c loads exactly the requested logical byte count, creating a record from runtime defaults if absent. 0x51f34 updates a record. Both give FDS (logical_length+3)>>2 words. Thus 5/6 logical bytes occupy 8-byte FDS data spans and 74 bytes occupy 76. The physical FDS record header, CRC, flash page state, asynchronous errors, and padding bytes copied from adjacent MCU RAM are not modeled. Caller-supplied extra bytes are retained in supplied_storage_tails as forensic input only; the API does not fabricate MCU padding.

Startup 0x52038 reads version with ldrh and cable with ldrb +2, verified from raw instructions. A version other than 4 calls 0x52000, which deletes file IDs 0x4000..0x6000, except 0x5000; it then writes version 4. Zero cable raw becomes 10. Other nonzero cable bytes are not validated: raw 159 becomes 169 for one press, then 10 on the next. The model preserves this literal behavior rather than normalizing malformed records. 0x58ab4 increments only the first 32-bit word of its eight-byte record, wrapping at 32 bits. startup_effects records high-level modeled work, not every asynchronous FDS call/event.

The profile template is the 74-byte initializer at flash 0x6ddc0, RAM 0x2000338c. Profile 0 has the same initialized bytes; profiles 1..5 initially contain only their index followed by zeros. Their channel route semantics are provided by the separate controls model. Factory-reset routine 0x527cc copies its mutable template into profile 0, then changes the template header for profiles 1..5. Literal routine nuance: the RAM template is left with ID 5 and enabled byte 0. If this exact routine is called again without reboot or another mutation, profile 0 receives that header on the second call. The model keeps the mutable template and tests this recurrence. This is a static reconstruction, not a claim of a reproduced user-visible controller defect.

The rest of the factory-reset menu path calls 0x570a8, 0x58898, 0x5d02c, 0x58718. It resets language byte 0, the full five-byte audio/display default block, display timer state, and the radio byte. It does not reset cable length, calibration records, or boot count. Unknown language bytes remain untouched. The default audio/display block is copied from RAM 0x200035c0, initialized at flash 0x6dff4.

Calibration capture reconstruction

0x516d8(0) starts the callback timer with 0xc000 ticks, sets current state 0 and final state 9. 0x516d8(1) uses final state 0. 0x517b0 captures the current state through 0x4e5a0, advances it if below the final state, or persists via 0x51694 and requests coefficient recomputation otherwise. Full mode therefore has nine useful capture steps (0..8) and a final state-9 no-op capture before completion. The model advances only when its explicit tick/advance_calibration method is called; it does not infer wall-clock timing.

The four raw samples are read at MCU RAM addresses (0x2000fd0e, 0x2000fd10, 0x2000fd0a, 0x2000fd0c) in that order. No physical stick naming is assigned.

State 0 writes center words (12,13,26,27). Each sample must satisfy 30000 < sample < 35000. Otherwise the function uses the corresponding original compiled calibration default copied to RAM 0x2000fc78 during 0x4da84, not the previous saved calibration value. Defaults are 28 u32 words at flash 0x6dd1c; all were verified against the binary.

0x5fe38 gives the nine display target coordinates copied into CalibrationModel.DISPLAY_POINTS. 0x53b2c copies calibrated centers to downstream state in word order (26,27,12,13); centers_for_downstream() reproduces that order. 0x51694 stores words 14..27 under key 4000 and words 0..13 under key 4001, then stops the timer.

Calibration coefficients and nonlinear transform

0x4e7b8 constructs four triples per 14-word gimbal block through 0x4df8a (Y from X) and 0x4e294 (X from Y). Raw Thumb instructions resolve Ghidra's misleading hard-float ABI: input double registers d0..d5 contain three coordinate pairs and returned d0..d2 contain coefficients. The zero-valued literal pools used for center-axis points were independently decoded from the binary. fit_quadratic() implements the recovered closed-form solve in source operation order.

There is a consequential sign convention: stored b is the negative conventional linear coefficient, confirmed by the sign-bit inversion at 0x4e142. Thus the interpolation curve is a*t*t - b*t + c. The subsequent transform initially evaluates a*t*t + b*t + c, then subtracts the linear term in its normalization denominators. The model preserves both operations literally. Tests use an asymmetric linear boundary to detect accidental correction of this convention.

For each bank, write its words as w[0..13] and centers as (cx,cy)=(w12,w13). The recovered three-point fits are:

Boundary Point 1 Point 2 Point 3 Fit
Positive Y (cx-w4,w8-cy) (0,w2-cy) (cx-w5,w9-cy) Y from X
Positive X (cx-w5,w9-cy) (cx-w0,0) (cx-w7,w11-cy) X from Y
Negative Y (cx-w6,w10-cy) (0,w3-cy) (cx-w7,w11-cy) Y from X
Negative X (cx-w4,w8-cy) (cx-w1,0) (cx-w6,w10-cy) X from Y

The numeric portion of 0x4f190 is implemented by transform_calibrated_pair(). It uses relative coordinates x=cx-raw_x, y=raw_y-cy, chooses the appropriate X/Y boundaries for the quadrant, evaluates their polynomials, and applies their rational correction. A 400-count endpoint margin precedes integer remapping (0x4df5c) to minimum 345, center 1984, maximum 3622. The returned trace includes quadrant, relative coordinates, corrected coordinates, and final u16 outputs. Explicit float32 rounding is applied where the ARM instructions convert to single precision; the remaining operations use host double precision.

The arithmetic contract is finite IEEE-754 nearest-even input with uint16 samples and uint16-scale calibration words. Degenerate fits, zero normalization denominators, and nonfinite values are rejected. Exceptional MCU floating-point modes, NaN propagation, overflow, denormals, and corrupted records outside that domain are not claimed. The solver and transform were statically recovered; no original firmware was executed for numerical comparison.

CalibrationModel.transform_samples(samples) accepts the same sample order as capture and returns 0x4f190 argument-output order: bank1 X/Y, then bank0 X/Y. Caller 0x56038 passes output pointers (0x200145e8,0x200145ea,0x200145e4,0x200145e6), so reorder the result [2,3,0,1] to obtain the MCU stick array beginning at 0x200145e4. Those values then pass through the filtering stage below before report production. The numeric transform alone is not the complete sampled-input chain.

Downstream averaging, conditional replacement, and center drift

The separate input_filter.py models these operations without reading sensors or scheduling callbacks:

Routine Exported function size Recovered role
0x566b8 62 bytes Signed32 running sum: subtract overwritten ring sample, add new sample, store new sample, signed division by window length
0x566f8 180 bytes Four calls to the helper using a shared u16 index, followed by index increment/wrap
0x53b58 284 bytes A one-count center adjustment within a narrow output-center window
0x56038 prefix Part of a 1556-byte routine Acquires transformed outputs, updates averages, conditionally replaces output and advances drift counters before HID work

Window length is initialized to 100, from flash 0x6dfe4 to RAM 0x200035b0. Four 400-byte int32 rings begin at 0x20014610, 0x200147a0, 0x20014930, and 0x20014ac0. Four sums are at 0x20014600..0x2001460c; averages are at 0x200145f0..0x200145fc; the shared u16 index is at 0x20014c54. Reset 0x27378 calls 0x272cc to zero RAM 0x20003978..0x200210ec, covering all this state. Startup therefore divides by 100 even before 100 real samples arrive. The independent helper models signed32 wrapping and division toward zero. A smaller explicit window is a synthetic testing/replay option, not a recovered user setting.

0x56038 supplies the moving-average arguments in bank1 X/Y, bank0 X/Y order. For each MCU output slot, it then compares the newly calculated average with the current unfiltered value. Only if their absolute difference is less than 8 does it replace the current output with that average and increment the corresponding byte counter at 0x20014c50..53. Other samples pass through unchanged and do not reset that counter. If the counter is already 30, it calls the drift helper, resets the counter, and then increments it. From zero, the first drift call therefore occurs on accepted sample 31, then every 30 accepted samples. Counts are explicit API observations; no wall-clock period is inferred.

0x53b58(output,current_center,reference_center,orientation) returns the current center unless output differs from 1984 and lies strictly between 1939 and 2029. Within that window, if the signed difference reference-current lies outside -199..199, the current center moves one count toward the reference. Otherwise, X orientation moves center +1 below 1984 or -1 above it; Y orientation reverses this direction. The valid callers use orientations 0 and 1. The bounded API rejects other orientations rather than exposing the source's unsupported zero-return branch as a usable feature. No flash write occurs in this helper.

InputFilterModel.step() takes stick_raw, calibration_centers, and reference_centers, each in MCU order: bank0 X/Y, bank1 X/Y (center words 12,13,26,27). Its output includes filtered values, new centers, acceptance booleans, counters, per-step drift-call booleans, and cumulative call counts. Since centers_for_downstream() returns the opposite bank order, reorder its result [2,3,0,1] for this API. Centers remain caller-supplied on each step; the filter never mutates CalibrationModel, recomputes coefficients, or persists records implicitly. The complete sensor transport, scheduler cadence, and coefficient-refresh lifecycle remain integration boundaries.

STM framing and queue evidence

0x583ac writes a shared 16-byte buffer at RAM 0x20014cdc:

CC 0E command value [11 retained bytes] CRC
                  offsets4..14       offset15
CRC input = offsets2..14; polynomial D5, initial0, MSB first.

It does not clear bytes 4..14. Audio generated just before a cable-length command remains in this tail, with a new CRC. StmFramer preserves this behavior and accepts a caller-specified initial buffer when reset-zero state is not appropriate. CRC routine 0x5840c gives 0xbc for 123456789; independent cable vector from zeroed state is cc0e040a0000000000000000000000f4.

0x58370 queues command 4 + cable raw. 0x58334 queues command 3 + transfer-mode value. 0x57124 builds command 2 with language at byte 3, zero byte 4, volume byte 5, and nine bytes of audio token at 6..14. It populates this shared buffer even when the audio is subsequently suppressed because volume is zero or enable flag 0x20014cd9 is not 1. It consumes the queued audio in either case.

0x57568 maps 26 event IDs to fixed voice token strings. 0x57124 checks the copied token length, including NUL, satisfies 1 < length < 10. ID 20 (PreDisarm, length 10 with NUL) fails this gate. The offline model retains the first nine token bytes in the shared buffer and returns no frame, while refusing to reproduce any out-of-buffer local copy. Unknown event IDs are treated as unsupported; no meaning is invented for the source's potentially uninitialized length in that case. Token strings are metadata, not actuation.

Five descriptors at 0x66288..0x662d8 resolve to the queues below. 0x31a4c returns error 4 on a full queue when descriptor word 4 is nonzero; otherwise it overwrites the oldest entry. 0x31990 and 0x31a04 establish the ring capacity interpretation.

Descriptor Role Capacity Element bytes Full behavior
66288 RX frames 200 16 Reject new
6629c command records 200 13 Reject new
662c4 first audio-string queue 10 11 Reject new
662d8 second audio-string queue 10 11 Reject new
662b0 input-to-event lookup queue 2 2 Overwrite oldest

The model's event queue accepts already-resolved event IDs: full lookup 0x57978/0x57dd8 is not implemented here, and its two-byte firmware element is therefore not falsely exposed as an equivalent model wire record. Its recovered capacity/overwrite and scheduling behavior are retained.

One polling call to 0x57124 consumes at most one RX frame, then considers transmission. It checks CRC and recognizes statuses 1,3,4,5. The shown function does not test byte 0. The bounded model accepts a complete 16-byte frame with length byte 14, records whether byte 0 equals CC, and does not impose an extra firmware prefix filter. Other lengths, arbitrary stream fragmentation, or malformed lengths causing out-of-buffer reads are outside the model.

  • Status 1 sets readiness to 1 when payload begins 01 01 02 04. When readiness is 1 and the suppression flag is false, each poll emits command 1, value 0. Initial readiness is 0xff from the initialized RAM image.
  • Status 3 clears the handshake-suppression flag. If not busy (0x57114), dequeue priority is: command, first audio string, second audio string, resolved event audio. At most one item is consumed. Incoming status 3 can queue a one-time first-boot command 3, value 1 through 0x58af8.
  • Statuses 4/5 are retained but have no outgoing branch in this function. Bad CRC and unknown types leave previous status unchanged.
  • An RX status 3 also tests two UI state bytes for (1,2) and may exit a transfer page. The model exposes this as an unmet external condition event; it does not guess whole-page state.

Public API and examples

from tac_reconstruction.settings import SettingsModel
from tac_reconstruction.stm import StmModel, StmFramer

settings = SettingsModel()  # modeled post-record-initialization state
stm = StmModel(language=settings.language, volume=settings.volume)
for effect in settings.press(8):  # select Cable length and activate
    if effect["kind"] == "stm_command":
        stm.queue_command(effect["command"], effect["value"])

# Synthetic ACK supplied to the offline model, not sent to any device.
stm.feed_rx(StmFramer().command(3, 0))
frames = stm.tick()  # list[bytes], first queued cable command
state = settings.snapshot()  # JSON-compatible observation
records = settings.persistence_records()  # {(file_id,key): logical bytes}

settings.press(1)
settings.press(1)  # center capture confirmation
settings.advance_calibration([32000, 32001, 32002, 32003])

SettingsModel.menu_event(3|4|5), press(item_id), snapshot(), persistence_records(), advance_calibration(samples), factory_reset() are stable entry points. CalibrationModel is independently usable with start(0|1), tick(samples), persistence_records(), centers_for_downstream(), coefficients(bank), transform_pair(bank,raw_x,raw_y), transform_samples(samples), and snapshot(). Pure numeric helpers are fit_quadratic, calibration_coefficients, and transform_calibrated_pair.

input_filter.py provides moving_average_update(history,running_sum,index,sample), MovingAverage4(...).step(samples), center_drift(output,current_center,reference_center,orientation), hold_and_drift(samples,averages,counters,calibration_centers,reference_centers), and InputFilterModel(...).step(stick_raw,calibration_centers,reference_centers). Both models offer snapshot().

StmFramer.command(command,value), cable_length(raw), voice_pack_mode(bool), audio(token,language=...,volume=...), event_audio(id,...), crc8(data), and parse_frame(bytes) expose framing. StmModel adds queue_command, queue_cable_length, queue_voice_pack_mode, queue_audio(priority=...), queue_resolved_event_audio, feed_rx, tick(busy=...), and snapshot. tick returns byte frames; metadata is in last_effects.

Validation and remaining boundaries

35 settings/STM/calibration tests cover literal defaults, all cable/volume transitions, unknown-field retention, startup version migration, malformed nonzero cable values, FDS lengths, navigation, confirmation, transfer-mode cancellation, factory-reset scope and mutable-template recurrence, boot counter wrapping, full/center calibration vectors and bounds, record round trips, CRC vectors, shared-tail retention, partial invalid-audio buffer changes, ACK and readiness gates, muted audio, queue order/capacities/overflow, first-boot handling, and rejected/unknown RX behavior. Seven of these specifically exercise the nonlinear math: a known polynomial with its stored sign convention, swapped-axis fitting, independently calculated symmetric quadrants/clamps, a curved-boundary exact-rational oracle, asymmetric linear behavior, default-center output/order, and explicit invalid-domain rejection.

11 additional filter tests cover zero-filled startup/full-window division, a separate moving-window slice oracle, signed division/wrap, seeded ring state, strict drift/hold bounds, axis orientation/reference limits, first-call and repeated-call cadence, counter retention across rejected holds, MCU channel ordering, and invalid-input rejection. Reproduce with python3 -m unittest tests.test_tac_settings_stm tests.test_tac_input_filter -v.

The modules use only Python's standard library and have no device/network/filesystem operations. The supplied original binary remains immutable. Tests establish consistency with the recovered routine subset and independent byte fixtures; they are not differential execution against a physical TAC or the original ARM image.

Remaining: full startup options screen and global page-navigation graph; sensor transport and coefficient-refresh lifecycle; exceptional floating-point cases; per-channel event-to-voice lookup; physical audio playback/STM firmware; actual cable equalizer effect; FDS physical flash format/errors/timing; complete malformed STM input behavior; interrupt/task scheduling and timing; full OLED drawing; electrical interfaces. State effects are exposed to the enclosing behavioral model for composition rather than silently performing those missing operations.

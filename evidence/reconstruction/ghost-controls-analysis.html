Offline reconstruction: Ghost transport and controls

This pass implements the static, deterministic behaviors listed below in tac_reconstruction/controls.py and tac_reconstruction/ghost.py. It does not execute the vendor image or communicate with hardware. Validation uses synthetic frames and saved decompilation/instruction evidence. The implementation is a behavioral model, not replacement firmware.

Image: evidence/firmware/nordic/Tac_Ctrl.bin, SHA-256 4c79b25623f07bfc62e8f223e8fbda30b0aba643277d9e13f1fadb6bd15931dd, Cortex-M load base 0x27000. A literal at virtual address A is read from file offset A - 0x27000. Unless stated otherwise, function evidence below is evidence/firmware/ghidra-export/<8-digit-address>.c. The focused receive callback also has a full saved instruction listing at evidence/firmware/ghidra-focused/0004be5c.asm.

Public interface

from tac_reconstruction.controls import InputState, ChannelRoute, routes_from_profile
from tac_reconstruction.ghost import GhostModel

model = GhostModel()
inputs = InputState(stick_raw=(345, 3622, 1000, 2000), buttons_word=0,
                    wheel_raw=(1024, 2047))
routes = tuple(ChannelRoute(source) for source in range(1, 17))
model.set_inputs(inputs, routes)  # explicit example routing, not an asserted default
frame = model.tick()             # bytes only; no transport
model.stage_home_e7(123456789, -765432100)
home = model.tick()
  • controls.affine_int, resolve_channel, resolve_channels, routes_from_profile expose the input resolver.
  • ghost.pack_frame and pack_control_frame expose framing and control packing.
  • GhostModel.set_channels(values) accepts sixteen unsigned 16-bit channel values. set_inputs(inputs, routes) applies the recovered resolver first.
  • stage_home_e7(latitude_e7, longitude_e7), stage_home_degrees(latitude, longitude), stage_bind(identity, hash_value) and stage_special(type, ten_payload_bytes) stage an outgoing packet. The pending flag is a single slot: the last staged operation takes priority.
  • queue_frame(frame) adds a validated logical frame to the higher-priority queue; returns False when its 100 slots are occupied. CRC is replaced at send time, as in the firmware.
  • tick() performs one scheduler invocation and returns one frame or None. It does not claim any elapsed time.
  • receive_frame(frame) models a complete 14/27-byte receive callback. receive_uart_chunk(chunk) models the original fragment behavior, including its limitations. These differ intentionally from the more general analysis decoder in scripts/ghost_protocol.py.
  • state is a public 75-byte bytearray, mirroring RAM at 0x200056a8. state_bytes returns an immutable copy. firmware_display() produces the traced numeric UI interpretations; snapshot() includes raw_state_hex, counters, flags, queues and events.

The default input values, packet templates and telemetry state are zero, an explicit abstract initial condition. They are not a measurement of a booted, centered or calibrated TAC. Settings profile defaults are owned by the separate settings model; routes_from_profile() parses their logical 74-byte records without importing settings.

Input sources and inversion

0x521e4 selects the source byte at profile offset 2 + 3*(channel-1) and uses the next byte as a nonzero inversion flag. The third byte is preserved by ChannelRoute.metadata_raw but does not participate in this numeric resolver. The six profile records and template were independently recovered by the settings pass; 0x5273c loads file 0x5002, keys 0x4003..0x4008.

5 Buttons u16 0x2001415c, bits 8..9 1→24, 2→224, 3→224, other unchanged

The three-state inversion first maps 1..3 → 3..1, converts to a byte, then calls the mapping helper. An invalid raw state zero consequently becomes 4, rather than being clipped. Binary inversion maps 0..1 → 1..0 before the helper. These are observed code quirks, retained by default.

0x520b8 uses signed integer multiply/divide with truncation toward zero, not Python floor division. The resolver returns a u16: out-of-range inverted stick values wrap and are not clipped. Supported u16 resolver inputs fit the traced signed multiplication intermediate. The generic Python affine helper does not pretend to reproduce arbitrary overflowing C expressions outside that domain.

The decompiled char return types of 0x52158, 0x5218a, 0x521bc misleadingly render byte 0xe0 as -0x20. Raw Thumb instructions load bytes, use MOVS #0xe0, and return without sign extension: the correct numeric resolver result is 224, not 65504. Both button references at literal addresses 0x52558 and 0x52734 resolve to the same 0x2001415c, so no second button state is invented.

This starts after ADC/input sampling and calibration. Physical axes, switch labels, debounce, calibration sampling and center-validation algorithms are not reconstructed here.

Control framing and scheduler

0x4c4a0 emits 81 0c <type> <10-byte payload> <CRC>. 0x4c428 computes CRC-8 polynomial 0xd5, initial zero, most-significant bit first, no final XOR, over type and payload only. Header address/length are not protected.

Types 0x10, 0x11, 0x12 each contain channels 1–4 as four consecutive 12-bit values, least-significant bit first, occupying payload bytes 0..5. Payload bytes 6..9 contain the low byte of channels 5–8, 9–12 or 13–16 respectively. The first group is masked to 12 bits, the selected bank to 8 bits. There is no universal byte-channel multiplication by sixteen.

The scheduler at 0x4c124 starts its response timer, then chooses:

  1. A queued raw frame, recomputing its CRC and using frame[1]+2 bytes.
  2. A special pending flag: 1→type13, 3→type23, 4→type21, 5→the type in the shared special buffer.
  3. With flag zero, cyclic types10→11→12→10.

A special or queued packet does not advance the control phase. Unrecognized flag2 sends nothing and remains set. The model exposes this behavior rather than implicitly recovering to control output.

The separate templates are at 0x2000a230 (13), 0x2000a244 (23), 0x2000a258 (21). Types50..56 share 0x2000a268. Type23 forces payload byte0 to1 at transmit; other template payload bytes survive until overwritten. 0x4d760 writes bind fields as little-endian u32 at frame offsets4 and8, leaving payload byte9 intact. The model therefore preserves that reserved byte across stage_bind.

Queue descriptors in the image give stronger bounds than the earlier packet-only analysis:

0x31990, 0x31a04 and 0x31a4c show a capacity+1 circular buffer with one reserved slot; mode1 rejects a push with return code4 when full. Existing contents survive. The RX type24 handler ignores that status. The model returns an explicit queue-full diagnostic while preserving the same queue contents. For outgoing frames, malformed lengths are rejected in the model instead of reproducing unbounded memory reads/writes.

The timer/reconfiguration portion of 0x4c124, 0x4d7cc, and downstream radio timing at 0x4db50 is not emulated in physical time. timeout_running indicates start/stop events only. Clock drift, radio timing synchronization, UART electrical timing and disconnect expiry remain gaps.

Home staging

The call path 0x5ab18 → 0x5a550 → 0x4d888 receives floating point coordinates, scales by10,000,000, converts to signed integers and stores latitude first, longitude second, as little-endian 32-bit words in type50. Frame bytes11..12 are set to zero. stage_home_e7 starts after that numeric conversion; the USB model can therefore supply the exact converted words. stage_home_degrees reproduces binary32 inputs/product and truncation toward zero. Non-finite/out-of-range casts are explicit unsupported inputs, not invented ARM cast results.

Independent signed fixture:

81 0c 50 15 cd 5b 07 dc 6e 60 d2 00 00 cc
latitude_e7 = 123456789
longitude_e7 = -765432100

Staging and constructing this frame does not imply radio delivery or aircraft acceptance.

Receive callback and state stores

The instruction listing at 0x4be5c establishes several intentional quirks:

  • Event0 stops the response timer and sets the link flag before checking payload, address or CRC, even for zero-length data.
  • Whole14 and27-byte chunks are checked by fixed size, ignoring the header length byte. A valid CRC calls 0x4cbf8; only address80 reaches its handlers.
  • A direct bad14-byte frame increments a 32-bit error counter. The direct bad27-byte branch omits this increment. Both fragmented lengths increment it on failure.
  • For other nonzero lengths, a first byte80/90 stores a prefix and its length. Otherwise the chunk is copied after that prefix. Dispatch is attempted only if prefix length plus current chunk length equals14 or27.
  • The append branch does not update the remembered prefix length. Thus arbitrary three-part fragmentation is not supported by the traced code; each later chunk overwrites after the original prefix. Concatenated-frame recovery is also absent.

The model reproduces these branches. Its 100-byte assembly limit is a guard at the inferred next-RAM-object boundary, not a claim that the original checks that bound. The general offline capture decoder intentionally uses a different, more capable resynchronization algorithm.

The dispatcher routes types20/21/22/23/24/25/26/32/33. State bytes are held at RAM 0x200056a8. BE→LE below means the handler constructs an unsigned big-endian integer from payload bytes and stores it in the little-endian MCU's RAM.

Type24 arriving in a valid short14-byte frame would make the firmware's fixed23-byte queue copy read beyond the logical payload. The model records an unmodeled-read diagnostic, rather than manufacturing adjacent firmware memory. Unknown types and non80 addresses leave state intact.

UI values and audio markers

0x620e8, swap helpers 0x63288/0x632c2, integer converters 0x63c48/0x63c70, and raw string/divisor literals establish the UI numeric behavior. The byte-order helper instruction listings are preserved under evidence/ghost-decoder/byte-order-helpers/.

Display field Exact computation on raw state
Drone Volts bswap16(state u16+28) /100
Drone Amps bswap16(state u16+2a) /100
Drone mAh bswap16(state u16+2c)
GPS Lat / GPS Long bswap32(state u32+2f/+33), unsigned, /10,000,000
Altitude, m bswap16(state u16+37), zero-extended
Heading, degrees bswap16(state u16+3b) /10
Satellites state byte+3d

The voltage/current divisor literal 0x62418=0x40590000 is the high word of double100; heading 0x6245c=0x40240000 is the high word of double10. The GPS double divisor is low word0 at0x623f8/high word0x416312d0 at0x623fc. Distance label pointers 0x62438→0x6d520 and 0x6243c→0x6d52c resolve to Drone Dist and km. These values mirror code, not a assertion that an arbitrary on-wire value is physically valid. In particular, unsigned GPS UI can show impossible geography. Raw state is always retained; receipt tracking provides type presence only, not age/fix validity.

Type21 radio-power changes and type22 VTX-power changes emit audio markers after the previous nonzero value differs. The first nonzero value establishes a baseline without an announcement. Literal tokens are RadPU/RadPD at0x6aa18/0x6aa20 and VTXPwrU/VTXPwrD at0x6aa28/0x6aa30. Numeric token selection is directly recovered from 0x4ced4: recognized values1,10,25,100,350,1000,1500,2000,2500,3000,5000,10000; values below1000 append miliW, others append W, even when the numeric value has no recognized number token. The model preserves that behavior through power_audio_tokens.

Frequency changes in types22 and33 call 0x4d8c8: Beep followed by at most five decimal digit tokens. The two previous-frequency variables are distinct (0x4cec4→0x2000fc72, 0x4d324→0x2000fc76). Events expose these recovered tokens; PCM assets, playback, voice-pack lookup and audio queue scheduling belong to other reconstruction scopes.

Verification and limits

python3 -m unittest discover -s tests -p test_tac_ghost_controls.py -v passed 20 tests. Expectations include literal independently computed CRC frames from evidence/ghost-decoder/fixtures-review.json, signed home field order, all source IDs and inversion cases, integer truncation, mask widths, scheduler priority, reserved byte retention, both queue capacities, raw state/UI endian traps, audio vocabulary, unsigned GPS boundaries, pre-validation link status and fragment/error-counter quirks. CRC fixtures were originally produced using polynomial long division, independently of the production CRC routine.

The pass does not recover the whole firmware. Open gaps include ADC acquisition and calibration, physical control identities, radio/aircraft responses, exact scheduling durations and timeout expiry, all meanings of special types13/21/51..56, field semantics beyond traced UI consumers, effects of malformed firmware memory accesses, and all board/pin electrical behavior. No new physical RJ45 mapping is inferred from this model. Initial state and events are simulation inputs/outputs, not evidence that a live device entered the represented state.

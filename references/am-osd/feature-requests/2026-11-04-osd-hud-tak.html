Compact HUD, stationary-drop world-down reference and AUX-selectable TAK views

Problem and intended use

Firefighting operators need a less obstructive analog OSD with MGRS readback and nearby TAK marker awareness. The current source layout has dense telemetry and separate centre cues; it does not implement the proposed flight vector, GPS-height circle or TAK pages.

Request future consideration of the display contract below, backed by an offline gallery and reproducible design fixtures. Current drop use assumes the vehicle is stationary at release. True CCIP, in-flight package-impact prediction and automatic release are outside this request's implementation scope. This is a proposal, not flight acceptance.

Requested normal flight HUD

Region Content
Top left Own full MGRS zone/band + 100 km square, then grouped easting/northing
Top right VTX channel; RX RF band/channel; link quality
Middle left GPS satellite count
Middle right GPS height above the captured same-datum ground reference; ignore barometric height
Bottom left Average cell voltage above consumed mAh
Bottom centre Heading-relative home arrow followed by home distance
Bottom right Two nearest fresh TAK markers: short ID, relative arrow and horizontal distance, nearest first

Remove the fixed centre crosshair, old latitude/longitude pair and unrequested base readouts. Do not display FWD, GPS VEL, VEL: LOW SPEED, DROP REF, DOWN or CCIP ADVISORY notifications. Existing package state/profile information can remain in the clear lower area shown in the references; switch/timer state must not be presented as proof of physical package presence or detachment.

The RX field must show an explicit unavailable placeholder until a verified RF source exists; an RC AUX channel number is not the receiver's RF channel. MGRS must keep the full prefix and leading zeros. Grid resolution must not be confused with position accuracy.

Forward velocity cue

  • Show only the distinct projected ground-velocity marker, using valid heading, 3-D velocity and the forward camera's own lens/mount calibration.
  • At low speed or with an unusable direction, suppress the vector quietly. No centre fallback and no low-speed warning banner.
  • Resolve the actual camera/view and coordinate frames; GPS course alone is not aircraft nose azimuth. Nearly immediate camera changes do not need a transition card.

Stationary-drop downward reference

  • Both downward states always project the same NED world-down unit ray [0, 0, 1] through the attitude/camera transform. Only roll/pitch changes diamond XY. GPS altitude, reference height, speed and release timing never offset this diamond.
  • Use the enlarged outlined diamond and centre dot. With usable GPS height/reference, add a circle centred on it; height changes circle diameter only. Without usable height, hide only the circle/diameter and keep the diamond at the same XY.
  • Surface advisory is FLAT for the current plane model. Reserve TER for an implemented backend actually using a valid height grid; having a grid file present is insufficient. Terrain support must preserve the attitude-only diamond.
  • GPS height is aircraft GPS altitude minus a captured reference in the same datum. Do not substitute barometric altitude or imply terrain-following AGL from a launch plane.
  • The reference circle uses assumed base/residual-drift allowances for a stationary release. It is an illustrative engineering footprint, not a calibrated confidence percentage or measured drop-accuracy claim. Final sizing/validity policy requires separate review.

TAK situational-awareness pages

  • Heading-up God's-eye layout: ownship arrow fixed at picture centre, markers rotate with aircraft azimuth, lightweight dashed range rings, bounded marker count and labels. Leave the camera background undimmed in this view.
  • Forward radar-style layout: ownship near the bottom with more range ahead; the example uses a ±50° fan, 3 km range and four dashed distance intervals. This plots TAK positions, not sensor detections. Off-scale chevrons/+ labels convey bearing only.
  • Both layouts are independent of camera angle and will commonly overlay forward-camera video. They must not be treated as camera-registered marker projections or terrain maps.
  • In SA pages, average cell voltage is the only retained legacy FC field. The two nearest TAK rows remain new SA content at bottom right. The list considers all fresh bounded contacts independently of the current radar sector/map range; sort by horizontal range, then stable short ID for ties. Expired/invalid records clear instead of being held as current.
  • Add an MGRS detail card for own position and the selected marker, with full independent prefixes, datum, grid resolution and freshness. Stale selected-marker data clears its grid.
  • Eventually support a configurable AUX page selector: Normal HUD / God's eye / Forward radar. No AUX channel is assigned by this proposal. Check camera/tilt/dropper conflicts, switch hysteresis, stale RC and atomic page clearing/restoration. The MGRS detail control is a separate mapping decision, not a fourth position on a three-position switch.

Thinner font candidate and board boundaries

The gallery previews public-domain Fixed Medium 9x15 text in the existing 12×18, 2-bit, 256×54-byte font contract. A 7x13 alternative and current-font comparison are included. The exported replacement C table compiled for Cortex-M4 against the real font header: 13,824 bytes .rodata, zero .data/.bss, and extracted bytes equal the exported table. Existing non-text symbol codes and the empty logo block are preserved.

This is a one-table replacement candidate, with no runtime font engine. Keeping both tables for runtime selection would add another 13,824 bytes of flash. The binary is font data, not a flashable MCU image. Installed PAL/NTSC, analog-link/goggles/DVR readability and rendering timing still need acceptance. Mock scenery/dimming and desktop canvases are visualization aids, not proof of PCB video-blending capability or MCU RAM use.

Use a bounded, trusted bridge/FC interface for marker snapshots, identity, source age, sequence, position frame and deletion/expiry. Prefer upstream MGRS conversion where appropriate. Do not add raw CoT XML/history or a regional map database to the scanline path. The current stationary flat-plane reference requires no terrain grid. A later grid backend needs its own memory, coverage, datum and update design; linker margins are not free-runtime allocation measurements.

Suggested implementation sequence and acceptance

  • [ ] Freeze per-camera projection/view identity and telemetry frame/time/validity contracts.
  • [ ] Port the reviewed HUD/font with verified original symbol compatibility and state clearing.
  • [ ] Verify world-down XY invariance across height/reference changes and height loss; verify roll/pitch motion through the installed camera, not just a desktop renderer.
  • [ ] Verify GPS datum/reference capture/reset and circle scaling/invalid-height policy.
  • [ ] Add bounded TAK ingest, nearest ordering, heading-relative arrows, ties, expiry, deletes, invalid positions/heading and out-of-order source records.
  • [ ] Port SA primitives/page takeover, MGRS detail and configurable AUX selection; test normal-page restoration and camera/AUX independence.
  • [ ] Measure scanline timing, telemetry load, stack/RAM margins, PAL/NTSC behavior and installed analog font readability. Run separate controlled stationary-drop acceptance.

True CCIP, moving-release guidance, package trajectory fitting, automatic release and regional height-grid storage remain deferred. Do not overload the world-down diamond with a finite trajectory point as part of implementing this request.

Reference evidence and limits

The companion offline gallery contains 11 labelled states, 46 PNGs, static overlays, interactive altitude/roll/pitch and TAK controls, source manifests, documentation and the font candidate. All scenes, marker locations, telemetry and performance allowances are synthetic. C01–C03 are source reconstructions, not live captures of an installed unit.

Existing reference checks: deterministic regeneration; nine historical PNG hashes; six host camera/settings/protocol tests; 117-height world-down invariance/clearance; 12 height/error plus six attitude browser/C comparisons; 64 SA render combinations; 360-heading nearest-marker checks; stale/tie/invalid/zero-range cases; desktop/mobile browser checks; and the isolated ARM font-table compile. These do not accept firmware features, physical drop accuracy, live TAK/AUX transport or a particular airframe.

Related calibration work: PR #2. The gallery's frozen source baseline is 2f1e4f8361589b0ce607198b478bd1a2bb029618, not the latest PR head.

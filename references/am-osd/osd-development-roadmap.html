OSD flight-guidance roadmap — 2026-11-04

Application: discrete fire-retardant bags/canisters. Current AM_OSD provides a nadir reference and inferred payload status. The canonical display set defines proposed forward velocity and downward world-down references. True impact guidance is deferred future work, outside the current stationary-release scope. Images are design fixtures, not package-accuracy or flight-acceptance evidence.

Camera work starts with PR #2, head 2f1e4f8, open at the initial 2026-11-03 review. It adds experimental Justice 4:3 fits; Generic remains the default. Optical tests and installed-camera acceptance stay separate.

The current interim implementation is an offline flat-terrain GPS-height prototype in the gallery. It removes all fixed centre crosshairs from proposed views. Both downward diamonds always project world down from roll/pitch; GPS height changes only the circle diameter. Surface text is FLAT, with TER reserved for actual height-grid use. There is no CCIP ADVISORY banner or ballistic point displacement. It needs one same-datum ground reference, with no terrain grid. See model and PCB storage budget. PCB porting remains deferred.

Architecture and input contract

The FC owns navigation state; the OSD owns camera projection and presentation. Start with telemetry diagnostics and a common scheduler/cache. Measure sample age, jitter, loss, bandwidth and scanline margin before raising baud rate or moving work between processors.

Pinned Betaflight 2026.6.2 has ordinary MSP attitude, altitude/vario and GPS speed/course messages. Separate replies are not a complete synchronized 3-D state. A small optional read-only MSP v2 reply could expose time/sequence, attitude, 3-D ground velocity, altitude reference, sensor ages/validity and heading quality. Explicitly convert GPS NED, estimator ENU, IMU and camera axes. Estimator trust scores are not impact-confidence percentages.

Forward velocity needs a trustworthy orientation reference: GPS course is not multirotor body heading. The current downward reference assumes stationary release and uses attitude for diamond XY, GPS surface height only for circle scale. Do not relabel launch-relative altitude as AGL. A downward ranger can measure a different surface from the eventual impact point.

Keep calculations outside the scanline ISR and publish complete symbol state at field boundaries. Use bounded primitives and measure worst-case rendering with DisplayPort traffic. The current renderer has one nadir sprite; vector, diamond, uncertainty and off-screen primitives remain new work.

View and failure policy

  • Forward: only the distinct ground-velocity marker; remove the fixed boresight. Low speed quietly suppresses the vector, with no low-speed warning banner.
  • Downward: both states always show the same world-down diamond from attitude only. Height, speed and release timing never translate it. Usable GPS height/reference adds the provisional circle; missing height hides only the circle. Ignore barometric height. Display only FLAT now and TER only when a valid height grid is actually used. Remove the fixed FC crosshair through reviewed layout integration.
  • Camera selection: switch the view directly; no transition card for nearly immediate camera changes. An unresolved or invalid selector still must not draw the wrong camera's guidance; sync lock alone cannot identify the camera.
  • Ordinary FC telemetry follows its own validity. Preserve a clear region around moving guidance and test dense warnings, clipping and off-screen motion.

The retained bundle selects CH6/AUX2 USER4 at 1600–2100 µs; AM's current crosshair gate uses >1700 µs or <1300 µs. Stage 2 must reproduce selector semantics and verify polarity per installation. CH11/AUX7 tilt needs camera-angle calibration or feedback if it moves the camera used for projection.

For the interim flat mode, use GPS altitude minus a captured same-datum ground reference; show height at middle right and label the view FLAT. Require usable height inputs for circle scaling. If height is missing or its error interval reaches the surface, retain only the diamond. Do not substitute barometric height. Never replace the world-down ray with a finite trajectory endpoint in these states. Its additive error budget is a visual-development assumption, not calibrated accuracy. Later replace the plane with validated surface data without changing the distinction between guidance and reference.

The compact flight HUD defines MGRS at top left, VTX/RX/LQ at top right, satellites at middle left, altitude at middle right, cell/mAh at bottom left, home arrow/distance at bottom centre, and the nearest two fresh TAK marker arrows/ranges at bottom right. MGRS, marker/navigation and receiver RF band/channel sources need explicit contracts; the reference uses RX --/-- until verified. Normal flight views use this layout; TAK retains its separate voltage-only policy.

Deferred future package-guidance work

True CCIP and in-flight package prediction are outside the current implementation scope. The following is parked roadmap context; the current prototype remains stationary-release world down with a height-scaled circle.

Current payload labels mirror switches and timers. Add actual heartbeat/latch/package feedback through a designed interface. MSP peers on separate FC UARTs are not automatically a routed telemetry link.

Develop a flat-surface/no-drag replay reference, then fit measured package profiles. Include vertical/horizontal velocity, wind-relative drag, station offsets, real separation delay and variability. Bags and canisters can need different models. Use representative inert equivalents and reserve independent drops for evaluation.

Specify accuracy as an error distribution over a documented envelope. Do not infer a 95% ellipse from a drawing or trust flag. First contact and useful retardant coverage are separate outcomes when packages bounce, rupture or meet canopy. Open-field acceptance does not establish forest/smoke/convective performance.

After camera acceptance, the immediate software work is view resolution and telemetry diagnostics, followed by the forward velocity marker. These references implement no firmware feature and declare no stage physically accepted.

TAK situational-awareness branch

The God's-eye and forward radar-style references define a separate SA page, clearing all normal FC telemetry except average cell voltage. Ownship stays centred in the heading-up overhead page; the forward fan reserves more screen range for contacts ahead. Both use light dashed distance guides and bounded marker lists, with explicit off-scale, stale-source and missing-navigation handling.

The offline gallery simulates a configurable three-position AUX: Normal HUD / God's eye / Forward radar. No channel is assigned and no received AUX or live TAK data is used. All TAK layouts are independent of camera angle; forward camera use is the expected default. The background selector changes scenery only, never map/fan geometry. Mock landscapes are viewing context, not georegistered terrain. The additional MGRS card shows full own-position and selected-marker references for radio coordination, with datum and grid resolution explicit. It is a separate detail preview; no fourth AUX position is assigned.

Thin bitmap font candidate

The font comparison and candidate table preview Fixed Medium 9x15, with 7x13 as a smaller alternative. Public-domain ASCII bitmaps are encoded into the current 12×18, 2-bit, 256-glyph table; existing non-text symbols remain. A replacement table is 13,824 bytes, matching the current table; no runtime font library or extra font RAM is needed. Keeping both tables for runtime selection would cost another 13,824 bytes of flash. The actual firmware table is unchanged.

Verify glyph/code compatibility, MGRS digit distinctions, PAL/NTSC interlace and readability through the installed analog link/goggles/DVR before adoption. Font selection is independent of TAK/CCIP transport and does not establish accepted map primitives or flight guidance.

2026-11-04 world-down contract

P03/P04 are world-down references in both valid-height and missing-height states. Their XY is invariant with altitude, reference height, speed and timing; only roll/pitch changes the projected ray. Altitude changes circle diameter/visibility. FLAT is the current surface advisory; TER requires real, valid height-grid use. Future terrain support must preserve the attitude-only diamond. A later true CCIP solution needs a separate reviewed cue and trajectory/acceptance work; it must not silently redefine this diamond.

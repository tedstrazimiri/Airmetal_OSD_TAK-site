Tac.Ctrl USB findings

Latest powered test: powered-usb-bench.md records the props-removed live test, local parameter replies and truncated capability response. The receive-only tests below remain historical evidence for the original isolation work.

Date: 2026-10-11. Host: Ubuntu Linux x86-64. Device: USB product string Orqa Tac.Ctrl, VID:PID 35b6:0004. User confirmed controller and ground radios powered, aircraft unpowered. All device nodes below are snapshot values and may change after reconnect; the helper scripts resolve the target dynamically.

Later firmware correlation: the supplied v1.3.6 package has now been decrypted and its Nordic application disassembled. Its device and HID report descriptors match this capture exactly. A local heartbeat builder emits the same fixed payload fields seen in the isolation tests. The normal CDC receive handler selectively processes MAVLink requests, including locally generated parameter/capability responses; a transparent aircraft tunnel is not established. Read current firmware findings. Installed version and end-to-end radio behavior remain unverified. Earlier unknown-source statements below describe the initial hardware-only evidence.

Its match to the installed firmware is unverified. The nearby MRM-2S HEX image is an aircraft artifact and was not substituted for controller firmware.

USB enumeration

Observed at bus 003, device 023, sysfs 3-1. USB 2.00 descriptor, 12 Mbit/s full-speed operation, one configuration, three interfaces numbered 0, 2 and 3. No interface 1 appears in this configuration; the numbering gap alone does not establish a hidden interface.

Interface Class Linux driver / node Endpoint Type, maximum packet, interval
0 HID gamepad usbhid, /dev/input/event24, /dev/input/js1, /dev/hidraw10 0x81 IN Interrupt, 64 bytes, 1 ms descriptor interval
2 CDC ACM communications cdc_acm, /dev/ttyACM1 paired with interface 3 0x82 IN Interrupt notifications, 64 bytes, 16 ms descriptor interval
3 CDC data Same serial function 0x83 IN / 0x03 OUT Bulk, 64 bytes each

Endpoint 0 is the standard control endpoint, maximum packet 64 bytes. IN means device to laptop; OUT means laptop to device. Descriptor intervals and packet maxima are not measured application update rates or throughput.

Stable serial symlink observed:

/dev/serial/by-id/usb-Orqa_Orqa_Tac.Ctrl_000000000000-if02

The serial descriptor is all zeros, so it is not a reliable unique physical-unit identifier. bcdDevice=1.00 is a USB device revision, not a verified firmware version. The configuration advertises self-power, remote wakeup and 100 mA maximum USB draw; these descriptors do not measure charging or battery behavior.

No UVC video, USB audio, mass storage or USB networking class was present. Other firmware/boot modes and proprietary tunnelling inside CDC remain untested. lsusb -v could not directly open the USB device with current permissions; standard descriptors and the full HID report descriptor were available through sysfs. /dev/hidraw10 is root-only; no permission rules or drivers were changed.

HID report layout

The 56-byte report descriptor is retained in evidence/usb/hid-report-descriptor.bin and .hex relative to the project root. SHA-256: 1e12645e986407d42f6938acf1316cab3bea3c59ea4e368793e60419043c62ca.

It describes a Generic Desktop Game Pad, with no report ID, only Input reports, and no declared Output or Feature reports. Expected input payload: 144 bits / 18 bytes. This length is derived from the descriptor; raw USB/HID reports were not captured.

Report bytes, zero-based Content Declared logical range

4-5 Y 0-2047

Linux joydev reports seven axes, codes 0-6, and 16 buttons. The duplicated Slider usage is consistent with both raw fields mapping to one Linux axis; the exact collision behavior and independent slider availability need raw HID capture. Do not assign roll/pitch/throttle/yaw or switches from these generic names alone.

The REA five-second sample contained 23 initialization events and 3 subsequent change events. Initialization events are cached state, not 23 newly observed control operations. The earlier three-second sample is retained separately. Joydev normalizes axes into a signed range; those values must not be interpreted as the descriptor's 0-2047 raw values. See the primary Linux joystick API and HID descriptor documentation.

CDC serial: MAVLink 2 verified

A bounded receive-only capture received 7 packets, each 21 bytes long. All 147 bytes are accounted for as MAVLink 2 HEARTBEAT messages (message ID 0, payload length 9). Each packet passes the MAVLink CRC calculation with HEARTBEAT CRC extra 50. A deliberately altered offline payload failed the checksum check.

Intervals between received packets were 1160, 1192, 1190, 1156, 1191 and 1194 ms; mean approximately 1180.5 ms. This is a short receive-time observation, not a link performance measurement. No position, attitude, battery, parameter, status-text or version message appeared in this eight-second window. That bounded negative does not establish those messages are unsupported.

Definitions were checked against the official MAVLink packet serialization specification, HEARTBEAT definition and enums, and generated HEARTBEAT header, accessed 2026-10-11.

Attribution limit: the aircraft was unpowered. The heartbeat may be generated by Tac.Ctrl, a powered ground module, or a ground-side proxy/template. Its ArduPilot and quadrotor fields do not prove that the controller runs ArduPilot or that the aircraft has that firmware. USB serial transport of valid MAVLink is verified; end-to-end aircraft telemetry, command forwarding, ATAK integration, or a complete MAVLink dialect is not.

Actions and limits

  • USB/sysfs descriptor reads and read-only Linux joystick access.
  • One 8-second serial receive session, opened O_RDONLY, with no write() calls, commands, heartbeat transmissions, configuration requests, firmware uploads or baud changes.
  • Host canonical buffering, translation and echo temporarily disabled, original terminal settings restored and read back successfully. Opening/closing CDC ACM can still affect DTR/RTS; USB control transfers were not captured. Initial host setting B9600 is not a verified required baud rate.
  • Device remained enumerated as bus 003 device 023 after the capture. This does not prove uninterrupted application state or rule out internal resets.
  • Offline decoding and one CRC corruption check. No aircraft operation, flight-control changes, radio settings changes or RJ45 connection.

The ground-radio-disconnected observation below supersedes the initial attribution limit. A later revision-matched vendor artifact can help explain whether the current heartbeat is a local status template, a telemetry proxy, or another firmware behavior.

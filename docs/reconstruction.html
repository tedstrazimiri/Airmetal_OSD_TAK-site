Runnable TAC.Ctrl reconstruction

The recovered Nordic firmware now has a runnable offline behavioral model in tac_reconstruction/. It reconstructs the main interface paths and substantial settings behavior. It is new, evidence-derived Python source: the original vendor source/build system is not recovered, and this is not a flashable replacement.

Run from the project directory on Linux with Python 3.10 or newer; runtime code uses only the standard library:

python3 -m tac_reconstruction demo
python3 -m tac_reconstruction verify-captures
python3 -m tac_reconstruction coverage
python3 -m tac_reconstruction catalog 5a6d0

The demo produces JSON showing each event, outgoing bytes, settings, telemetry display values and final logical persistence records. To save it, add --out /tmp/tac-demo.json; output files must not already exist. The included scenario uses synthetic controls, telemetry, STM acknowledgements and calibration samples. Its 21.35 V example is synthetic and must not be mistaken for the earlier user-reported hardware reading.

The composition harness connects settings to STM commands, processed controls to HID/Ghost, Ghost telemetry storage to USB position generation, and USB home requests to Ghost staging. Ghost audio markers remain exposed as events; automatic audio timing/routing beyond traced paths is not invented.

Run your own scenario

Copy examples/reconstruction-demo.json, edit its events, and run:

python3 -m tac_reconstruction simulate /path/to/scenario.json --out /tmp/tac-result.json

The top level needs schema_version:1 and an events list. Optional records loads logical settings as {file_id,record_key,data_hex} entries; profile_index selects 0..5 in the harness; strict_crc:true deliberately rejects bad USB CRCs. Each event has op and optional label.

Operation Fields / effect
inputs sticks: four processed uint16 values; buttons: uint16 word; wheels: two uint16 values. Optional 16 routes with source_id, inverted, metadata_raw; otherwise use selected profile.
usb_rx, ghost_rx, stm_rx hex: received bytes. Ghost input is a UART callback chunk; STM requires a complete 16-byte frame.
usb_tick, ghost_tick, stm_tick One subsystem invocation, returning frames_hex; STM optionally accepts busy. No elapsed time is implied.
ghost_queue hex: queue an inert complete outbound frame.
ghost_special type and ten-byte payload_hex: stage a recovered special packet.
menu_press item_id: select and press an item. IDs 0 full calibration,1 center,2 voice pack,8 cable,3 volume,4 language,5 display,6 radio,7 reset.
menu_event event:3 up,4 down,5 activate. Confirmation behavior is preserved.
calibration_sample samples: four raw uint16 calibration samples after entering calibration mode.
calibration_transform samples: four raw uint16 sensor values in capture order. Returns nonlinear correction traces and output order; does not silently feed the separately modeled downstream filter or HID/Ghost.
filter_sample sticks, calibration_centers, reference_centers: four values each in MCU array order. Advances averaging/counters and returns filtered outputs and adjusted centers; no implicit feedback or record persistence.
audio_enable enabled: explicit external gate; its activation timing is not simulated.
audio_token, audio_event token plus optional priority, or resolved event_id. Output is a serial payload, not played sound.
snapshot Read current module state and logical records.

Python callers can import the individual modules or ControllerModel. For example, GhostModel.stage_bind() produces the recovered pending state without sending it anywhere. SettingsModel.persistence_records() can be passed into a new model to test reboot/load behavior; storage padding, flash headers and wear behavior are not emulated.

Preserved firmware quirks

  • 97 parameters advertise count 96, and sequence numbers are allocated before queued transmission.
  • Capability output stops after 44 bytes of a declared 72-byte packet.
  • The dispatcher can accept parser status 2 for CRC-failed input. This remains the default source-faithful model behavior, explicitly logged as bad_crc_dispatched; strict rejection is optional.
  • HID scaling can reach 2048 despite a descriptor maximum 2047; some switch values preserve prior bytes.
  • Ghost wheel routes ignore inversion, and receive fragment handling has limited state progression.
  • Telemetry UI and USB position conversions contain unsigned/byte-order/unit quirks. Model output is not normalized geographic truth.
  • Reset preserves selected settings and mutates a reusable profile template, affecting a second reset without reboot.

Verification and limits

The complete suite passes 118 tests, including the earlier Ghost decoder tests. The final 29-event demo and deterministic asset regeneration check also pass under REA process capture.

python3 -m unittest discover -s tests
python3 scripts/reconstruct_tac_assets.py --check

verify-captures compares 31 heartbeats, 241 parameter packets and 2 malformed capability prefixes, validating capture hashes and stream offsets. Packet sequence IDs are seeded from captures for those comparisons; separate tests exercise sequence allocation and queue order. Static-only modules use source-derived arithmetic/transition expectations and literal packet fixtures. The integrated scenario checks crossings between modules.

The model has no serial/network/device transport. It cannot operate the aircraft or flash the controller. Calibration math covers finite valid records and normal nearest-even arithmetic; degenerate/exceptional inputs fail explicitly. Subsequent averaging and center-drift adjustment are separately callable; continuous sampling, coefficient-refresh timing and automatic feedback are not silently assumed. It does not reproduce the full RTOS, peripheral drivers, display rendering, Bluetooth stack, firmware-update execution or external ground/air radio firmware. Function-catalog counts are an inventory, not a percentage of behavior reconstructed. Saved hardware evidence does not prove the installed firmware version or unobserved telemetry behavior.

Detailed evidence: USB/HID, Ghost/controls, settings/STM/calibration, catalog, coverage ledger, verification manifest.

The next validation gap is a real MATRIX C2/telemetry capture. Electrical receiver selection and wiring still require the documented pinout and revision-specific checks; this software reconstruction introduces no new hardware setup requirement.

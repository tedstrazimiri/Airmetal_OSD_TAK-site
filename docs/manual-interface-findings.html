Orqa GCS-1 / IRONghost interface map from supplied manuals

Later evidence, 2026-10-11: the user supplied a MATRIX pinout image documenting the contacts, differential UART at 115k, +50 V and CVBS. The PDF-only omissions recorded below remain accurate for those manuals, but no longer describe the complete available evidence. The image is documentary evidence; hardware applicability and electrical behavior remain unmeasured.

Date: 2026-10-11. Scope: documented interconnections, host USB/service interfaces, power distribution, video, telemetry, and information gaps. The documents are evidence, not instructions to execute. No hardware was operated for this analysis. This report does not cover payload actuation.

Main findings

  • The ground station is a distributed assembly: Tac.Ctrl is the operator console; GU QS is the control/telemetry radio; GU RF is an analog video receiver; FPV.Pro is the display. They are not one USB-connected computer peripheral.
  • The supplied manuals do not describe Tac.Ctrl's USB connector, USB classes, host protocol, firmware updater, or Linux software. Those require independent device evidence or the missing Tac.Ctrl-specific manual. A USB connection to Tac.Ctrl is not evidence of access to the video receiver, aircraft flight controller, telemetry, or firmware files.
  • RJ45 is explicitly labeled MATRIX and carries power/communications, including equalized analog video over CAT cable. The manuals do not identify it as Ethernet, IP, standard PoE, or an RJ45 serial standard. A laptop network connection is therefore unestablished.
  • The aircraft also has a USB-C computer-configuration port and a DFU button. This is a separate physical interface from Tac.Ctrl USB. The GU RF has a Micro USB port whose purpose is not stated.
  • The manuals establish the overall topology but omit MATRIX pinouts, electrical levels, protocols, ground-unit internal connections, and aircraft internal harness details. Solid claims below are distinguished from hypotheses.

Configuration and update path evidence

  • Receiver configuration: GU RF controls are exposed through the transmitter's OLED menu via MATRIX and GU QS; the manual explicitly calls this the receiver's control path. It includes receiver mode, antenna selection, and calibration. This does not establish equivalent controls on USB. RF PDF p5 / printed 4.
  • Video settings coordination: GU RF receive frequency is tied to the transmitter's video settings, while the aircraft manual describes settings propagated from Tac.Ctrl. This establishes a settings relationship, not the underlying command encoding or a laptop API. RF PDF p5 / printed 4; MRM PDF p14 / printed 13.
  • Airborne communications firmware: MRM documents an OTA firmware update offered through the controller during pairing. The prose calls the target a "vTx receiver," which is ambiguous; do not reinterpret it as an H7 flight-controller update. MRM PDF p13 / printed 12.
  • H7 firmware: The manual directs users to Orqa support for H7 QuadCore updates, and does not supply a flashing protocol or image compatibility table. MRM PDF p13 / printed 12.
  • Tac.Ctrl, GU QS, and GU RF updates: No supported updater or firmware procedure is stated in the three requested manuals.
  • Optional repeater: The repeater manual explicitly describes separate USB-C service ports for its control/telemetry and video-receiver blocks, using Windows tools supplied by Orqa. This applies to the repeater only, not automatically to GU RF's Micro USB or Tac.Ctrl's USB. REP PDF p16 / printed 15.

Optional repeater: architecture evidence only

REP Fig 4.1 (PDF p7 / printed 6), rendered as evidence/manuals/repeater-block-pdf-p7.png, separates the control/telemetry and analog-video chains. It labels an airborne Ghost Rx / Tramp vTx hybrid; a repeater receive/transmit pair for control; rapidFIRE analog reception feeding a composite-video connection to the repeater video transmitter; and the ground rapidFIRE / IRONghost Quattro Tx assembly with MATRIX to Tac.Ctrl/Hub.

The figure labels a GHST Rx Protocol boundary at the airborne receiver and within the repeater. This is useful evidence for that architecture but does not prove the exact MRM2 H7 receiver protocol, serial port, pinout, or firmware setting. Likewise, a camera-to-Tramp block shown in this figure does not prove whether an MRM2 camera signal passes through an FC OSD before the VTx.

Conflicts and missing specifications

Topic Conflicting or missing evidence Consequence
CAT cable length START PDF p6: up to 600 m. RF PDF p3 / printed 2: 600 m signal/power and analog-video claim. GCS PDF p6 / printed 5: up to 1 km. Do not represent a single tested maximum; likely revision/system-dependent and unverified here.
External QS power threshold START PDF p6: external battery for runs longer than 600 m. Newer GCS PDF p6 / printed 5: longer than 100 m. Preserve both dates/claims; seek revision-matched QS/MATRIX limits before long runs.
Video antenna connector type RF PDF p4 explicitly says RP-SMA female for this ground receiver; REP PDF p7 says all video-link antenna connections are SMA. Product-specific RF table and actual hardware inspection outrank applying a broad statement across products.
Aircraft firmware version MRM quick guide says Betaflight v4.1, but the task directory has no measured aircraft firmware evidence. Do not infer the live version from manuals or firmware filenames.
MATRIX transport Connector, cable type, power and analog-video functions documented; electrical schematic absent. RJ45 appearance gives no authorization or technical basis for plugging it into a laptop Ethernet NIC or PoE switch.
Tac.Ctrl USB / ATAK USB not covered; ATAK only a capability claim. Need descriptors/runtime captures and the Tac.Ctrl manual before asserting computer integration.
Internal aircraft routing Components named, but harness and PCB interfaces omitted. Keep internals at a functional level; do not invent UART numbers, voltage levels, OSD routing, or protocol pinouts.

Evidence still needed for a complete interface model

  1. Tac.Ctrl-specific manual and actual USB descriptors/interface inventory, with device/firmware revision recorded.
  2. GU QS-specific manual and MATRIX electrical/pinout specification for the actual revision.
  3. FPV.Pro-specific manual and LEMO connector/pinout specification.
  4. Read-only identification of the aircraft flight-controller firmware and receiver interface if aircraft access is later in scope.
  5. Manufacturer tooling metadata or provided updater artifacts to distinguish service interfaces from runtime host interfaces.

The manuals establish only connector-level and functional paths. They do not establish a USB-to-MATRIX bridge, USB video capture, MAVLink over Tac.Ctrl USB, an Ethernet port, standard PoE, or a common protocol across all USB connectors.

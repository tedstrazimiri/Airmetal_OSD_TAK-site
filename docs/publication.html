Publication and evidence policy

The private source/evidence repository is tedstrazimiri/Airmetal_OSD_TAK. The public website is generated into _site/ and published through tedstrazimiri/Airmetal_OSD_TAK-site.

GitHub returned Your current plan does not support GitHub Pages for this repository when Pages was requested for the private source repository. A public static companion avoids changing the source repository's visibility or requiring an account upgrade. The site itself is public; source/evidence links to the private repository require GitHub sign-in and repository access.

The site export is allowlisted: authored Markdown reports, generated topology/pinouts and hardware tables, synthetic OSD reference assets, reviewed component datasheets and local browser libraries. It excludes raw USB captures/host inventories, native/managed decompilations, firmware and voice payloads, manufacturer manual copies, complete REA bundles, tool/database state and embedded-secret resources. Narrative references to private or local-only evidence resolve to a clear source-register page or the private GitHub file view.

The private repository includes the minimum vendor firmware/media fixture inputs for full regression reproduction. It excludes the actual embedded-secret resource, installer/bundle DLLs and full decoded carriers. The complete local source inventory and hashes are in the snapshot manifest. Local-only items are preserved in the original workspace; nothing was deleted to publish this repository.

Historical reports preserve measured/static/synthetic distinctions and unresolved semantics. Website adaptation changes navigation and removes workstation-specific links; it does not turn static firmware paths into measured behavior. The initial triage remains explicitly superseded by later successful decoding.

Updating

  1. Update source reports/reference assets in the private repository.
  2. Run the full offline checks and scripts/build_site.py / scripts/check_site.py.
  3. Review _site/site-manifest.json; only allowlisted files belong in the public artifact.
  4. Publish the generated site with scripts/publish_site.py using existing local GitHub authentication. No cross-repository token is stored in workflows or source.
  5. Verify the Pages build and the live diagram, then record the actual deployed commit/URL in the handoff.

GitHub Actions validates the private repository; site publication uses the authenticated publishing script. A source commit alone does not silently export newly added files into the public site.
